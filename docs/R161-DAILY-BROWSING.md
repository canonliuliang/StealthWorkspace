# R16.1 第二次预览的日常浏览验收

## 登录、访问记录与网站识别

此次改动来自一位每天使用视频网站的用户。他希望下次打开应用时仍能使用会员，但本机历史里不再显示昨天看过的页面。旧版在锁定后丢失两个测试站的登录 Cookie、本地偏好和网站数据库，清历史也让用户退出。Firefox 社区有类似的直接反馈，不能据此估计影响所有用户的比例。[Firefox 用户反馈](https://support.mozilla.org/en-US/questions/1201080)

Brave 的 Windows 用户也报告过关闭再打开就退出账号，另一条反馈来自需要在两次启动间保留登录的网页应用用户。Chrome 的清理界面将访问历史、网站数据、已缓存的文件和下载列表分别处理。本版据此把这四项分开验收，并在盾牌中说明清除账号的影响。[Brave 的 Windows 用户反馈](https://github.com/brave/brave-browser/issues/44789) · [网页应用用户反馈](https://github.com/brave/brave-browser/issues/33351) · [Chrome 的数据清理说明](https://support.google.com/chrome/answer/2392709?hl=zh-Hans)

主空间使用每个保险箱独立的网站配置，只在解锁后附加。退出时明确向 WebView2 清理浏览历史、下载历史和 HTTP 磁盘缓存；应用同时丢弃内存中的最近访问和关闭标签。第一方 Cookie、网页本地存储与网站数据库交给内核按网站的规则维护。选择内置平衡跟踪防护以兼顾登录支付、视频和嵌入内容的兼容性。[WebView2 数据种类](https://learn.microsoft.com/en-us/microsoft-edge/webview2/reference/winrt/microsoft_web_webview2_core/corewebview2browsingdatakinds?view=webview2-winrt-1.0.3719.77) · [Edge 跟踪防护](https://learn.microsoft.com/en-us/microsoft-edge/web-platform/tracking-prevention)

| 用户操作 | 在真实浏览器内检查的结果 |
| --- | --- |
| 打开两个需登录的网站，锁定、解锁，再退出并启动 | 两个本地服务器仍认证登录，网页保留各自的偏好、IndexedDB 和会员状态；网页脚本无法读取 HttpOnly 登录凭据。独立检查原生历史数据库中的测试访问数为零。 |
| 主动在 A 退出登录后重启 | A 仍退出，其普通网页偏好保留，B 仍登录。 |
| 在盾牌中确认清除 A 的账号和数据 | A 的登录、本地偏好和网站数据库清除；B 的三项均保留。 |
| 在空白新标签清除所有网站账号 | 取消时没有创建浏览器内核。确认后两站登录、本地偏好和数据库都清空，再启动仍为空。 |
| 关掉最后一个网页，只留空白标签后退出 | 原生历史从两条降到零。新进程仍可使用两个网站的账号。 |
| 异常终止一个测试进程后重新打开 | 终止前后磁盘各有两条已知访问。重开后旧访问为零，新访问两条。接着正常关闭后，新旧访问都为零。 |
| 使用不同保险箱或临时空间 | 登录状态各自独立。临时网站目录随会话结束清除。 |

可通过 `node tools/Test-LoginRetention.mjs <程序目录> <新的测试目录> --exercise-crash --exercise-clear-all --exercise-last-tab` 复核。脚本仅使用随机标识的合成库、两个回环地址和本地服务端。正常退出既查应用的成功回报，也检查浏览器自身历史数据库；异常退出只终止测试脚本启动的进程。故意留下两条访问再检查清零，防止把空数据库误判成成功。

用户可能在网站自己的账号里继续看见观看记录。已登录的网站能认出账号，离线内容、收藏和实际下载的文件也能表明用户与哪些网站有过往来。会话过期、网站撤销凭据或仅发会话 Cookie 时，用户仍可能需要再次登录。旧版已删除的账号无法恢复。

## 收藏、缩放和下载

使用全新的 Chrome 测试配置，在 Chrome 自己的书签管理器中导出 HTML，再用 Stealth 首页的文件选择器导入。应用报告新增 3 条链接、5 个文件夹。在收藏栏沿「视频 → 待看」选择测试视频，真实网页加载了预期路径。测试使用本地网页，没有读取个人浏览器或会员账号。[Chrome 导出书签说明](https://support.google.com/chrome/answer/96816?hl=zh-Hans)

分别从首页、网页菜单和下载列表操作。网页缩放检查页面实际报告的设备像素比，首页缩放检查原生滚动控件的倍率。下载测试经真实 HTTP 下载 4 MiB 文件，清空任务列表后到目录中重新找到文件，并对照原件验证加密导入。Windows 普通权限下确认资源管理器打开了正确路径；Windows 低权限拒绝外部打开时，用户仍能在应用中读取下载目录、切换位置和存入保险箱。

## 环境与代价

在 Windows 11 ARM64 上，用同一个 192,359 字节的合成 Chrome HTML 分别调用第一次公开预览包和本次修订的解析实现。文件含 2,500 条链接、100 个文件夹。每次新进程预热 4 次、采样 9 次，交换运行次序，每版共 18 个样本。

| 本地解析 | 中位用时 | 范围 | 读取结果 |
| --- | --- | --- | --- |
| R16.1 第一次预览 | 16.25 ms | 14.49–28.51 ms | 2,500 条链接，层级丢失 |
| R16.1 第二次预览 | 17.51 ms | 15.35–36.13 ms | 2,500 条链接、100 个文件夹 |

这些数字测量 HTML 解析，未包含文件选择、加密保存和绘制界面。保留目录结构在该样本上增加了 1.26 ms 中位解析耗时。

另外用 50,000 条合成收藏检查本次开发中发现的同步查找开销。第一版文件夹实现为星标按钮逐条解析网址，耗时中位数 29.17 ms，产生约 26.72 MB 托管分配。修订版复用当前不可变收藏集合的索引，同一查找为 0.009 ms、152 字节。依次查找 20 个文件夹的中位用时由 36.32 ms 降至 0.102 ms。这组数字比较同一修订开发期间的两种实现，测量数据查询，不含画出菜单的时间。50,000 条收藏首次建立目录索引的中位用时为 15.52 ms，总分配约 2.57 MB。

真实回环服务器还返回了有效期一天的可缓存资源。服务器收到的累计 GET 数在同一浏览器内依次为 0、1、1；正常关闭并重启后为 1、2、2。网页保存的离线副本在退出后仍能读到，主动清除一个站点或全部站点时才按相应范围移除。

使用 Apple Silicon 上的 Windows 11 ARM64、系统构建 26300 和本机 WebView2。此轮采用回环网站以固定身份、数据和网络响应，未使用真实付费会员，也未用该实验测量视频解码、续航或外网速度。把网站状态保存在本机增加了数据保留量。真实退出有清理开销，异常终止与下次浏览之间也有残留窗口。在一次包含异常退出恢复的测试中，正常关闭时原生清理曾耗时 5.69 秒，原先的 4 秒等待会留下记录。修订版保留有界等待，超时会报告失败并在下次导航前重试。
