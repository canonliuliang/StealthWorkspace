# Stealth 审计复核与修复报告 r14

日期：2026-11-14。版本：`2026.11.14-r14-preview`。

本轮针对用户补充的 5 项审计意见逐项复核、修改并验证。工作位于本项目的独立本地工作区，保留此前 r13 的修复。本轮没有发布远程版本、修改官网或覆盖正式安装目录；没有使用真实保险箱做破坏性测试。

## 1. 五项问题的处理结果

| 审计意见 | 复核与处理 |
| --- | --- |
| Edge 的 `UseShellExecute=true` 与 `ArgumentList` 一起使用必定异常 | **该断言不成立**。.NET 8 Windows 的 ShellExecute 分支会构建 ArgumentList；本机也分别执行了两种启动模式并验证参数生效。已将已知 Edge exe 的启动改为 `UseShellExecute=false`，直接启动程序，但不把这一调整描述成已证实的崩溃修复。 |
| 删除媒体、清空诱饵时忽略粉碎失败，留下无索引密文 | **成立，已修复**。新增持久删除记录。确认文件已移除才更新索引；被占用的文件保留条目并报告失败。清空诱饵部分成功时保留失败条目及诱饵凭据，可继续重试。原实现中 ClearDecoy 已在清空索引前尝试粉碎，实际缺陷是忽略结果，并非两处都先删索引。 |
| 只读文件无法粉碎 | **成立，已修复**。通过原生元数据句柄先检查文件类型和硬链接数，再清除同一文件的只读属性。失败时尝试恢复只读属性；多硬链接文件在属性改变前即被拒绝，内容不受影响。 |
| 重置吞掉删除失败，随后无法恢复备份 | **成立，已修复**。任何未完成的文件或配置移除都会报错，持久保留“重置未完成”状态。重新打开后仍能重试；全部清除后才允许初始化和恢复备份。 |
| 规范路径字符串比较误拒 SUBST / 8.3 别名 | **实现已修正，验证有一项限制**。以卷序列号和文件索引核对身份，通过 ReOpenFile 重新打开同一对象，并复核当前路径指向的对象。真实 8.3 短路径测试通过；宿主拒绝创建 SUBST 测试映射，因此该项明确跳过。重解析点和目录挂载点仍按安全策略拒绝遍历。 |

## 2. 删除与重置的恢复机制

直接将“删除索引”和“粉碎文件”交换顺序仍不完整：文件删除成功后，索引保存也可能失败。本轮新增 `Services/VaultService.Removal.cs`，在破坏性操作前把用户已授权的操作写入经当前 Windows 用户 DPAPI 保护的 `remove.dat`，并落盘刷新。

- 单项删除和清空诱饵：逐项执行，只移除已确认不存在的索引记录。检查“文件不存在”时区分权限拒绝，避免把无法访问误当作已删除。
- 索引写入失败：保留恢复记录，回滚内存索引；重新打开后仅对已确认消失的文件完成索引收尾，不在启动时擅自继续粉碎。
- 索引备份同步失败：保留恢复记录，避免旧备份重新带回已删除文件的条目。
- 未完成操作期间：拦截导入、改密和备份等其他写入，允许重试原删除操作或显式重置。
- 重置：先记录重置意图，锁定保险箱，再处理媒体和配置。媒体或配置移除失败都会保留未完成状态；恢复记录最后删除。重置是不可回滚的多文件操作，失败意味着可能已有部分文件移除，提示不会宣称已全部完成。
- 数据目录选择和迁移：识别只有恢复记录的旧目录，迁移时带上删除记录，避免遗弃尚未完成的重置状态。
- `.gitignore` 与发布输出检查增加 `remove.dat*`、`rotate.dat*`，防止私有恢复记录进入版本库或发布包。发布检查脚本已修改，本轮没有实际生成发布包。

## 5. 边界与后续复核

- SUBST 路径仍需在允许创建临时盘映射的 Windows 环境中实测；不能据本次 8.3 测试声称 SUBST 已验证。
- 若主索引损坏且只能从备份读取，同时存在删除恢复记录，程序保守保留数据并拦截新写入，不猜测应删除哪些文件。
- 这些测试验证应用层删除行为、数据保留和故障恢复；不证明 SSD、快照或外部备份中的历史数据被物理擦除。
- 当前交付是本地 r14 源码和已验证的调试构建；公开发行版本及正式安装未随之更新。
