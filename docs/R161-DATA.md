# r16.1 设置、备份与恢复验证

## 收藏与设置的恢复顺序

收藏和隐私设置共用 DPAPI 加密文件。Firefox 用户报告过升级后收藏消失，Mozilla 的恢复指南会先确认用户配置及现有备份。这给出了值得验证的工作流。Stealth 没有统计文件占用或收藏丢失的发生频率。[用户反馈](https://support.mozilla.org/en-US/questions/1356094) · [Mozilla 恢复指南](https://support.mozilla.org/en-US/kb/recover-lost-or-missing-bookmarks)

测试先保存两代设置和收藏，用 Windows 共享模式临时阻止读取最新主文件，同时允许重命名。r16 将最新文件移到损坏副本位置，随后允许写回旧设置。r16.1 区分不存在、格式无效和暂不可访问三种状态。遇到文件占用，当前进程只读，如果备份可读，此次只读启动采用上一代偏好。释放句柄并重新启动即可看到原来的最新收藏和设置。测试在写入尝试后逐字节比对了主文件，并确认没有产生误标的损坏副本。[Windows 文件共享模式](https://learn.microsoft.com/en-us/dotnet/api/system.io.fileshare)

另两个用例分别锁住仅存的加密备份，以及让旧明文设置与较新的加密备份同时存在。r16.1 在前者避免自动写入首次运行的默认设置，在后者优先读取较新的加密备份。旧明文文件保持原样，直到已有可解密的主设置。

## 创建、检查和恢复媒体备份

| 可复现的情形 | r16.1 的结果 |
| --- | --- |
| 创建备份期间锁定工作区，然后解锁到原空间或另一空间 | 两种用例都中止了旧会话的操作。原备份逐字节一致，临时 ZIP 已移除。 |
| 新归档已完整写出，在重新打开归档校验时取消 | 原备份仍在原位置。应用在目标卷完成读取校验后才提交替换。 |
| 备份之前，介质上的一份密文已末尾截断 | 新备份被拒绝。已存在的可用备份保持原样。 |
| 归档和清单的 SHA-256 相符，但载荷截断、索引长度不符、主盐无效、诱饵凭据丢失或同一空间含重复条目标识 | 五种输入的检查和恢复均被拒绝，没有提交新索引。使用的是合成存档。 |
| 一次恢复已放入部分密文，进程在提交索引前退出 | 用该磁盘状态重建测试，重新选择匹配备份后成功恢复。已有密文按长度和 SHA-256 核对并以只读句柄固定至提交，未覆盖原件。目录里出现无关文件或同名的不同密文均停止恢复。仍有密文时创建全新保险箱也会被拒绝。 |
| 同一备份含有旧 V1 变长分块与当前 V2 密文 | 备份、验证及恢复均成功。解锁恢复后的真实空间，读取完整旧媒体并与原始文件的 SHA-256 核对一致。 |

验证程序在本机 DPAPI 上下文中解密索引，检查档案及清单 SHA-256、密码校验字段、文件名关联、媒体头及明文长度。V2 读取固定头部，旧 V1 无总长字段，需要扫描分块头。普通备份检查没有各空间密码，AES-GCM 分块标签在实际解密读取时核验。备份仍依赖原 Windows 用户。进程异常终止后，上次恢复的加密暂存目录可能留在磁盘，恢复不会删除无法确认归属的残留。

## 前后对照

Windows 11 ARM64 使用相同的合成文件、真实 NTFS 共享句柄、已安装的 .NET SDK 和 DPAPI。两个独立源码目录均基于公开标签 `v2026.11.20-r16-preview`。基线只叠加新诊断和既有 V1 测试写入器的内部可见性，候选还叠加上述数据层修复。两次均运行 Debug 自检，未使用个人数据。

| 程序 | 通过 | 失败 | 环境跳过 |
| --- | ---: | ---: | ---: |
| r16 加同一组新断言 | 237 | 14 | 1 |
| r16.1 数据层独立候选 | 251 | 0 | 1 |

跳过项为测试目录没有现成 SUBST 盘符映射。上述数量仅对应这组隔离对照。集成版本的完整测试以发布验收记录和标签 Actions 报告为准。复现可在隔离源码目录运行 `dotnet build`，再以 `tools/Test-Core.ps1 -PublishDirectory <包含生成的 StealthWorkspace.exe 的目录>` 执行。输入的合成保险箱、归档和设置都由现有自检入口创建。

另外使用上次匿名下载并校验过的公开 r16 ARM64 ZIP 中的程序集创建双空间备份，再在独立进程使用候选程序集打开归档，恢复到新目录。主空间媒体为 1,300,007 字节，诱饵空间为 925,031 字节。用各自原密码打开后，分空间核对名称、条数、完整解密流与输入文件的 SHA-256 均通过。两进程读到的同一份备份 SHA-256 为 `a77b8933bf2a6d276f8d5bb5dcfa4b08b5254fa18de6aeac3827d7c5e9563072`。
