# r16 收藏夹与地址栏测量

收藏较多时，打开收藏夹、寻找名称相近的网页和输入一个完全不同的搜索词有不同的成本。Firefox 用户曾报告约 1,000 条收藏的配置下地址栏输入和回车出现延迟，另有超过 60,000 条收藏时侧栏操作迟缓的报告。它们支持测试这些场景，无法估计 Stealth 用户的收藏规模或问题发生率。[Firefox 地址栏反馈](https://bugzilla.mozilla.org/show_bug.cgi?id=1279864) · [Firefox 收藏侧栏反馈](https://bugzilla.mozilla.org/show_bug.cgi?id=1986910)

## 实现与范围

收藏夹打开时直接绑定设置中的有序不可变集合。输入更具体的查询时，面板只筛选上一轮命中的标题和地址。缩短或替换输入、更新收藏时会检查完整的当前集合。关闭面板会解除列表绑定，清空检索词和临时结果。地址栏继续在本地检索八条以内的建议，对于至少 256 条收藏的集合，可复用同一编辑过程中已确认没有匹配的查询前缀。来自其他标签的本次会话历史仍按最新内容检查。

## 环境与方法

2026 年 11 月 20 日，在 Parallels 的 Windows 11 Pro ARM64 虚拟机上运行。系统版本 26300，4 个虚拟逻辑处理器，约 6 GiB 内存。.NET SDK 10.0.401，ARM64 基准进程实际加载 .NET 10.0.12。两次独立启动 Release 基准程序，每个场景先预热 12 次，再交替顺序采集各 31 次。P95 取排序后第 30 个值。分配用当前托管线程的分配计数器测量。

基线使用公开 r15 标签 `v2026.11.14-r15-preview`（`631e123`）的地址解析和建议源码。收藏面板基线复现该标签的完整匹配与数组复制表达式；脚本从基线设置声明读取集合类型，r15 使用 `List<BookmarkItem>`，r16 使用 `ImmutableList<BookmarkItem>`。收藏和两条会话历史都是合成数据。每轮校对 118 个完整地址建议结果、100 对地址身份，以及三个收藏规模下每一步的筛选结果和顺序。

## 观察结果

表内为两次运行各自 31 个样本所得中位数的区间。每次按键序列的计时包含整个序列。分配量列取第一次运行中的每场景平均字节数。

| --- | ---: | ---: | ---: | ---: |

| 同上 | 50,000 | 1.79–1.99 | 2.52–2.71 | 576,856 → 163,515 |
| 收藏面板替换、删除、改变大小写再清空 | 50,000 | 3.12–3.55 | 2.41–2.52 | 1,640,224 → 435,137 |

在 50,000 条收藏场景，无匹配词组的 P95 从 12.36–12.73 ms 降至 2.34–2.46 ms；命中列表末尾的 P95 从 1.06–1.20 ms 升至 2.00–2.92 ms。收藏面板混合编辑的中位数降低，P95 却从 4.07–4.30 ms 升至 7.07–7.55 ms。集合与运行时分层编译都会影响完整扫描，虚拟机调度和 GC 带来样本波动。这里的主要收益是减少重复扫描和托管分配。未测量整机工作集、网页加载、滚动帧率、重启系统后的冷启动或续航。

## 原生 Windows 锁屏启动

当地时间 11 月 21 日，在同一台虚拟机上比较先前从 GitHub 下载的 r15 ARM64 包与本地 r16 ARM64 候选 ZIP 的实际解压程序。两者均自含 .NET 10.0.15。每个样本都启动独立 Windows 进程，使用新的合成数据目录和临时目录，观察到锁页、应用退出、保险箱上锁、浏览器控件释放和临时配置清理。先各预热一次，再交替顺序测量五对，未清空操作系统文件缓存。

| 进程创建至锁屏 XAML 报告就绪 | 第 1 对 | 第 2 对 | 第 3 对 | 第 4 对 | 第 5 对 | 中位数 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| r15（ms） | 375.4 | 964.4 | 492.2 | 352.2 | 461.1 | 461.1 |
| r16（ms） | 369.4 | 449.3 | 360.7 | 591.0 | 553.4 | 449.3 |

从 OS 进程创建到进入应用 `OnLaunched` 的中位数分别为 154.4 ms、161.3 ms。两个版本的锁页就绪中位数差 11.8 ms，小于各自样本间波动。样本不足以支持启动速度改善的结论。计时终点是根 XAML 元素 Loaded 中的就绪标记，精度为毫秒。此场景保持工作区上锁，不创建 WebView2，也没有测量第一帧实际显示、键盘响应或第一个网页就绪时间。原始报告保存每一进程的起点、两个就绪标记和两份二进制的 SHA-256。

## 复现

在项目根目录运行以下 PowerShell 命令。临时目录保存公开基线，脚本在 `artifacts` 生成带运行时间的目录，其中含原始毫秒数、P95、分配量与地址算法的源码校验值。再次运行时请使用新的输出目录。

```powershell
$benchRoot = Join-Path ([IO.Path]::GetTempPath()) ("stealth-r15-" + [guid]::NewGuid())
New-Item -ItemType Directory -Path $benchRoot | Out-Null
$baselineZip = Join-Path $benchRoot 'baseline.zip'
git archive -o $baselineZip v2026.11.14-r15-preview -- Services
if ($LASTEXITCODE) { throw '无法导出 r15 基线' }
$baselineSource = Join-Path $benchRoot 'source'
Expand-Archive -LiteralPath $baselineZip -DestinationPath $baselineSource
./tools/Test-BrowserPerformance.ps1 -BaselineRoot $baselineSource
```

原生启动用 `./tools/Measure-BrowserStartup.ps1 -BaselineDirectory <r15解压目录> -CandidateDirectory <r16解压目录>` 复现；应使用同架构的完整发布包并关闭已运行的 Stealth 窗口。
