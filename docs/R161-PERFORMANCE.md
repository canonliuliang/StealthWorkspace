# r16.1 收藏、地址栏与网页加载测量

本轮从 r16 已记录的收藏末尾命中退化继续追查。r16 每次重命名或增删收藏后，刷新星标会重新解析整个集合的地址。逐字输入网址时，只有完全无匹配的结果能在下次按键复用。大收藏夹在真实使用中确有报告，有用户描述了接近 68,000 条收藏时的搜索和整理延迟。该个案不足以估算 Stealth 用户的收藏规模。[Firefox 用户报告](https://bugzilla.mozilla.org/show_bug.cgi?id=1986910) · [r16 对照](R16-PERFORMANCE.md)

## 修改与边界

- 书签增删、重命名以及批量导入维护已有的地址索引。地址继续按协议、IDN 主机、端口、用户信息、区分大小写的路径和查询区分。旧设置中同地址的多个条目保持原有的重命名与删除语义。
- 星标、删除和重命名在后台提交 DPAPI 设置，写盘成功后才更新可见收藏。导入在一次写入内按原顺序合并，并跳过重复、非 HTTP(S) 和含用户信息的地址。保存直接生成 UTF-8 字节并清零应用持有的明文缓冲区。
- 地址栏在一次编辑中可复用上次已完整检查、至多八项的结果；每次仍重新检查其他标签产生的会话历史。收藏快照变化、删除输入或 Unicode 代理对改变匹配边界时会重新检查。大量收藏需要反复全量扫描时，同一快照可共享一份顺序排列的对象引用。50,000 条在本机约需 400 KB 引用空间。打开面板、第一次筛选或少于 4,096 条的集合无需创建此引用数组。
- 已知本地协议和带有用户名密码、缺少协议的地址在提交前拦截。也验证了端口写错的合成凭据地址，整个测试中均未调用搜索地址生成器。常见搜索运算符、邮件地址搜索和本机端口继续可用。[Windows URI 文档](https://learn.microsoft.com/en-us/windows/apps/develop/launch/launch-default-app) · [RFC 3986 用户信息](https://www.rfc-editor.org/rfc/rfc3986#section-3.2.1)

主空间沿用原 DPAPI 设置中的收藏。诱饵空间有独立的会话内收藏，锁定后丢弃。自检对比了诱饵空间增删改前后的主设置文件 SHA-256，验证两个空间即使使用相同的网页地址也不互相覆盖。锁定和重新解锁会使旧的导入会话失效。普通界面的空间隔离不覆盖拥有同一 Windows 用户权限的其他程序。

## 方法

2026 年 11 月 21 日，Windows 11 Pro ARM64 26300，Parallels 虚拟机，4 个虚拟处理器、5.99 GiB 内存。独立基准使用 ARM64 .NET 10.0.12 和 .NET SDK 10.0.401，发布包自包含 .NET 10.0.15。基线源码取自正式标签 `v2026.11.20-r16-preview` 的 `238f53b`。所有收藏、历史、数据目录和凭据均为合成数据。

每张表给出两次独立运行各自中位数的范围。检索每场景预热 12 次，再交替采集 31 对样本。实际保存每场景预热 2 次，再交替采集 9 对样本。保存计时包括设置序列化、Windows DPAPI、临时文件写入和替换、一次真实星标查找。添加和移除合计两次写入。两版生成相同规模与日期分布的收藏。磁盘、虚拟机调度和 GC 会影响耗时。分配量取当前托管线程累计分配的平均值。

### 地址输入与收藏筛选

| 场景 | 收藏数 | r16 中位数 ms | r16.1 中位数 ms |
| --- | ---: | ---: | ---: |
| 地址栏逐字输入无匹配词，21 次 | 200 | 0.427–0.440 | 0.426–0.446 |
| 同上 | 50,000 | 1.04–1.71 | 0.78–0.94 |
| 地址栏逐字输入并命中列表末尾，14 次 | 50,000 | 1.58–1.91 | 1.20–1.41 |
| 逐字输入列表末尾的网址片段并继续补全查询，27 次 | 50,000 | 12.59–17.40 | 0.87–1.10 |
| 收藏夹替换、删除、改变大小写再清空 | 50,000 | 2.51–2.62 | 1.51–1.61 |
| 新快照上的第一次无匹配筛选 | 50,000 | 0.626–0.662 | 0.686–0.686 |

每个耗时覆盖整段按键序列。长网址输入的 P95 从 14.06–29.24 ms 变为 0.97–5.44 ms。无匹配输入的一轮 P95 由 5.43 ms 升至 10.45 ms，另一轮由 1.32 ms 降至 0.89 ms，尾部抖动仍然存在。首次新快照无匹配筛选两版均约分配 1 KiB。每次基准验证 196 组完整建议和 100 对地址身份，另逐项核对收藏筛选顺序。

### 真实设置读写路径

| 场景 | 收藏数 | r16 中位数 ms | r16.1 中位数 ms | 当前线程分配 r16 → r16.1 |
| --- | ---: | ---: | ---: | --- |
| 重命名末条并持久化，随后刷新星标 | 200 | 5.41–6.85 | 5.10–6.13 | 0.30 → 0.05 MiB |
| 同上 | 10,000 | 25.33–27.70 | 16.23–17.55 | 18.10–18.54 → 4.95 MiB |
| 同上 | 50,000 | 96.55–98.05 | 55.58–57.09 | 83.14–84.91 → 15.15–18.70 MiB |
| 添加一条后移除，两次持久化与星标刷新 | 50,000 | 177.78–205.85 | 115.68–123.57 | 144.14–146.81 → 42.73–48.06 MiB |
| 新集合首次查询星标 | 50,000 | 24.45–25.63 | 16.78–21.23 | 23.61 → 19.39 MiB |

10,000 条收藏的首次星标查询，一次由 9.58 ms 变为 9.18 ms，另一次由 11.38 ms 变为 15.85 ms。首次建立索引仍需要遍历所有地址。50,000 条设置写入仍可能耗时数十至数百毫秒。以上为实际服务完成操作的时间，界面已将磁盘阶段移出 UI 线程。

### 实际 WebView2 加载

同一台机器上的 WinUI 回归使用回环 HTTP 服务和 48 张图片。每个样本先清理 HTTP 磁盘缓存，再导航和等待 WebView2 报告完成。r16 ARM64 解压包的三个应用样本分别为 432.6、459.4、414.4 ms。r16.1 开发构建为 422.6、430.6、394.8 ms，所有样本都加载了 48 张图片。每版只记录三次，先后采集且构建形态有别，不足以判断网页加载速度的变化。网络 DNS、实际站点负载和物理设备能耗不在本项测量范围。

## 复现

从项目根目录运行，脚本在 `artifacts` 下生成新的结果目录并记录源码 SHA-256、运行时、耗时和分配量。持久化脚本还保留每次原始样本与可核验的合成 DPAPI 文件。可通过 `-OutputDirectory` 指定新的目录。

```powershell
$fixture = Join-Path ([IO.Path]::GetTempPath()) ('stealth-r16-' + [guid]::NewGuid())
New-Item -ItemType Directory -Path $fixture | Out-Null
$archive = Join-Path $fixture 'r16.zip'
git archive -o $archive v2026.11.20-r16-preview -- Services
if ($LASTEXITCODE) { throw '无法读取 r16 标签' }
$source = Join-Path $fixture 'source'
Expand-Archive -LiteralPath $archive -DestinationPath $source
./tools/Test-BrowserPerformance.ps1 -BaselineRoot $source
./tools/Test-BookmarkPersistence.ps1 -BaselineRoot $source
```

## 多标签持续运行与权限读回

Windows 11 ARM64，WebView2 157.0.4341.60。使用独立的 r16.1 ARM64 候选便携构建，保留三个带 DOM 状态的网页，循环创建、加载和关闭一个临时标签。20.01 分钟完成 79 次循环，79 个采样点中应用私有内存为 56.2–100.6 MiB，托管内存 1.9–5.1 MiB，采样的渲染器私有内存 70.1–99.7 MiB。结束时保留页面状态读回正确，控件释放，会话目录清理成功。运行时拒绝了后台休眠请求，采样中实际休眠标签为零。20 分钟单轮实验不支持推断整日内存增长、续航或跨设备效果。

随后用含最终锁定和净化链接改动的候选包重跑完整 Browser 回归。页面调用地理位置 API 得到权限拒绝。在不配置 STUN/TURN 服务的本地 ICE 收集中观察到两个 mDNS 候选、零个数字 IP 候选，只记录计数。外部中继、网络代理、系统 DNS 配置及其他网络条件不在这个实验范围内。渲染器恢复后可继续暂停的下载并核对文件字节。浏览器进程整体退出后能创建新进程并重新浏览，这次观察中会话 Cookie 未保留。
